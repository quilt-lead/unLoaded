## Why

The user asked for a real JSON format holding the element graph and the calculation graph side by side, with the
Harborview tower demo converted to it and still usable as a demo. The element graph already had a format
(`unloaded.element-graph`). The calc graph had none: it existed only as the engine's `Export` and the
IndexedDB mapping runs.

## Decisions

- **B1. A new file format, not an extension of the project file.** A project-file calc revision must carry its PDF;
  a bundle names PDFs by sha256 and never carries bytes. The element graph is embedded unchanged.
- **B2. The calc graph uses the export's field names** (snake_case), so `exportToCalcGraph` and `bundleExport`
  convert without renaming. The top level stays camelCase (`elementGraph`, `calcGraph`) like the element graph's
  own meta.
- **B3. A bundle model revision stores the bundle file as its revision file.** The store and the project file
  carry the calc graph with no schema change. `meta.format: "bundle"` and `meta.hasCalcGraph` gate reading it
  back (`bundleCalcGraphOf`, cached per revision id).
- **B4. A calc PDF wins.** `projectSnapshot` uses the model revision's bundle calc graph only when the project has
  no calc PDF heads.
- **B5. Review state travels as decisions.** Bundle links marked confirmed or manual become decisions with negative
  ids, so they are older than any project decision and the reviewer's log wins on the same pair.
- **B6. The demo supersedes D19's "documents never mixed with calc links"** (calc-engine-integration note), at the
  user's request (2026-11-15). The invented documents are now calcs in the Calculation Graph. They stay
  unmistakably labelled:
  - provenance `method: "estimate"`, `rule: "bundle.demo"`
  - a caveat on every link
  - tier `stated`
  - the "Demo calcs" calc root, a DEMO chip, "DEMO DATA • NO PDF" and a "no PDF" note in the PDF pane
  - (the header DEMO DATA badge went with prod's header redesign, bd02afd; `view.hasDemoData` is still computed if a header badge comes back)

  D19 left whether Noah's files stay to Noah. The user converted and replaced them in this session; tell Noah.
- **B7. The app no longer opens legacy `{ nodes, links }` JSON.** The user chose this. The parser refuses it with a
  pointer to `scripts/convert-legacy-demo.ts` (run with `node`; Node 24 strips types). The converter is the old
  loader's logic plus the demo calc graph. Output is deterministic, and the counts match the legacy loader
  exactly:
  - 420 / 488 elements and 1773 / 2118 edges
  - A/B diff: +70 / −2 / ~29

## Gotchas

- **Bare calc keys come back as `d1#key`.** The store's `decisionLog` rewrites a bare calc key to `d1#key`
  (`legacyCalcRef`, for projects from before calc sets). Bundle calc keys are bare, so `projectService.bundleKeyed`
  maps those refs back when the bare key is a bundle calc. Without it, confirm/reject on a demo link silently
  does nothing. A test in `projectService.test.ts` covers this and fails without the fix.
- **Not in a bundle:** typical groups, group links and findings. The engine derives them from the PDF, and
  `bundleExport` returns them empty.
- **Impact screening** (`impactOf`) still uses only PDF calc sets. On a bundle-only project it reports the load
  path but no stale calcs.
