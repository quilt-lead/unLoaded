# calc-viewer

Links the Building 12 structural drawings to the calc packages that size them, with three static HTML pages:

| Page | What |
|---|---|
| `drawings.html` | Drawing set with clickable elements → linked calcs open at their bounding box |
| `calcs.html` | Calc packages with clickable calc boxes and evidence marks → the drawn elements they cover |
| `index.html` | Every element: **List** (filters, links both ways), **Hierarchy** (building → level → system → typical group), **Connections** (focus graph of real relationships) |

First scope: roof framing plan **S2.0.3** and enlarged stair plan **S5.0.1**, with their detail callouts.

## Double-click version (`viewers/`)

`viewers/drawings.html`, `viewers/calcs.html` (one tab per calc PDF) and `viewers/index.html` open straight from disk,
no server. They're generated by `build/make_viewers.py` (run automatically by `build.py`): code and styles inline,
data and PDFs packed as scripts in `viewers/assets/` (the `pdf-*.js` files are git-ignored copies of the source PDFs).

Following a link opens the *other* viewer in its own window, or reuses it if it's already open: a window this page
opened, or the one that opened it. Served over HTTP, any open viewer tab of the site is also found. Viewers you
double-click separately can't see each other from disk, so a link may open a second window then.

## Run (served, for development)

Needs Python 3 with PyMuPDF (`pip install pymupdf`). The three source PDFs stay at the repo root and are git-ignored
(copyrighted / permit set) – keep this local, don't publish it.

```sh
python prototyping/calc-viewer/build/build.py           # writes data/*.json and docs/plans-S.pdf (~1 min)
python prototyping/calc-viewer/build/serve.py           # http://127.0.0.1:8765/prototyping/calc-viewer/drawings.html
```

`build.py --force` regenerates `docs/plans-S.pdf` (otherwise it's reused unless the plan set is newer).
The server serves the repo root so the pages can reach the source PDFs, binds to 127.0.0.1 only, and disables caching.

## Data (`data/`)

| File | Holds |
|---|---|
| `documents.json` | The PDFs and their page labels (sheet numbers) |
| `elements.json` | Drawn elements with content-based IDs (`level/type/grid/orientation`, size kept out of the ID so a resize keeps the ID), fields, fingerprint, and every place they appear |
| `groups.json` | Typical groups (same size + level) – what a size-only calc links to |
| `calcs.json` | Calcs as ordered **spans** of page regions. A span runs on across pages; a gap starts a new span. One span = one stepper stop |
| `links.json` | Element/group ↔ calc links: role, confidence (sum of evidence weights), band, evidence (with boxes on both sides), caveats, hits, provenance |
| `summaries.json` | Hand-written (this session) plain-language summaries per link, merged in at build time. Later: the Claude API from the same evidence |

Confidence comes from the evidence, not from the summary. Bands: high ≥ 0.75, medium ≥ 0.5, low < 0.5.
Element colour = best **design** link; a loads-only link doesn't count as designed.

### IFC alignment

Each element carries an `ifc` block (IFC4) next to our own working `type`, which stays the ID/grouping key.
Each group carries the matching type object (`typeClass`, e.g. `IfcBeamType` named by the size). Mapping
(`IFC_MAP` in `build/build.py`):

| Our `type` | IFC entity . PredefinedType | Material |
|---|---|---|
| `beam` | `IfcBeam.BEAM` | steel |
| `wood-member` | `IfcBeam.BEAM` (all drawn in plan) | wood |
| `stringer` | `IfcMember.STRINGER` | steel |
| `post` | `IfcColumn.COLUMN` if "POST ABOVE", else `IfcMember.POST` (parapet) | steel |
| `hss-member` | `IfcMember.MEMBER` | steel |
| `callout` | `IfcAnnotation` (not a building element) | – |

`ifc.objectType` is the section as drawn, `ifc.storey` the `IfcBuildingStorey` name (the level). No IFC file is
written. These are the classes an exporter would use.

## What the first run found

- **Detail callouts → stud calcs (high):** the E-section ENERCALC calcs name their sections (`HSS HDR(A) – 1/S4.0.1`), so the roof plan's section callouts link exactly.
- **Stair (mostly high):** the stair calc sketches are drawn at the same grids and with the same `n/S8.8.1` callouts as S5.0.1. Size mismatches are flagged: plan MC18x42.7 and C12x20.7 (grid 5/A) vs calc C15x33.9.
- **Roof gravity (low):** the 2021 RISAFloor roof model uses different grids (1–5 / A–E) and layout from the approved roof plan (1–6 / A–F). W16x26 and W18x35 link by size only; **W12x14, W14x22, W8x35, W12x79 have no roof sizing calc** in these packages.
- **Unlinked:** wood trellis members, SMF callouts to S3.0.1, most S8.x detail callouts.
